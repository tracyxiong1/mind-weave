# 实施路线

先验证「整理 → 查看 → 修改 → 再次整理 → 引用继续讨论」的最小闭环，再扩展跨宿主自动化。下列事项都是待实施工作。

## 第一阶段：核心数据与编辑原型

先用整理好的示例对话和确定的图数据构建一个可交互预览，减少模型输出波动对交互验证的影响。

- 明暗主题、缩放、拖动、折叠和节点详情。
- 标题与摘要编辑、补充/连接/删除、撤销。
- 本地保存与重新打开；稳定的节点引用。
- 区分自动整理内容、用户修改和视图位置。

验收：编辑并移动一个节点，关闭后重新打开，内容和位置仍在；删除后可以撤销；复制的引用能解析到同一节点。

## 第二阶段：增量整理

- 将一轮对话转成带来源的增量变更。
- 验证输入后再应用到图；无效变更不能部分破坏已有内容。
- 重复轮次去重，保护用户修改、关系和删除记录。
- 保留不确定性，分开处理用户疑问和 AI 探索建议。

验收：至少覆盖学习型、方案讨论型和多次分叉的示例。重复整理不产生副本；人工改过的字段保持原样；来源可追溯；自动整理不会打开预览。

这一阶段优先为更新规则写有意义的测试，包括重放、删除、合并引用、过期变更与人工编辑冲突。

## 第三阶段：一个宿主中的手动闭环

选择可用能力最明确的一个宿主先接通，Codex 为优先验证对象。先确认实际接口，再决定使用 skill、CLI、MCP 或其他适配方式。

- 主动整理当前对话。
- 主动打开预览。
- 复制节点引用，在原对话中让 agent 读取上下文并继续。
- 验证 Devbox 到用户浏览器/预览面的访问路径。

验收：在真实宿主中完成一轮从对话到画布、再从画布回到对话的过程；明确列出支持项和限制。原生 `@` 自动补全和宿主内嵌界面尚未验证，不能作为现有能力承诺。

## 第四阶段：可选自动化与第二个宿主

- 验证每个宿主是否有可靠的完整轮次事件。
- 提供用户主动启用和关闭的配置入口。
- 对触发事件去重，避免整理自己触发新的整理循环。
- 自动更新只处理已有授权的对话内容，保持预览打开状态不变。
- 复用核心数据契约接入另一个宿主。

验收：配置前不自动运行，启用后按完整轮次更新，关闭后立即停止；缺少可靠触发能力的宿主仍可手动使用。

## 建议的首批任务

1. 确定数据契约和三个小型对话样例，明确用户编辑保护规则。
2. 做可编辑的明暗画布原型，验证节点密度和详情布局。
3. 实现并测试增量变更应用器。
4. 接通一个宿主的手动整理、预览与引用闭环。
5. 验证自动触发，再增加第二个宿主。

## 暂不排入首版

多人实时协作、云端账户和同步、跨会话知识库、完整白板绘图，以及另起一套聊天系统。
