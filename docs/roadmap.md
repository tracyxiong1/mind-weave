# 实施路线

先验证「整理 → 查看 → 修改 → 再次整理 → 引用继续讨论」的最小闭环，再扩展跨宿主自动化。2026-10-13 已完成本地编辑原型、Codex 手动整理所需的增量应用器，以及真实 Codex 会话的手动闭环。

## 第一阶段：核心数据与编辑原型

状态：已实现。运行方式见项目 README，实际检查与截图见 [验证记录](validation/README.md)。

先用整理好的示例对话和确定的图数据构建一个可交互预览，减少模型输出波动对交互验证的影响。

- 明暗主题、缩放、拖动、折叠和节点详情。
- 标题与摘要编辑、补充/连接/删除、撤销。
- 本地保存与重新打开；稳定的节点引用。
- 区分自动整理内容、用户修改和视图位置。

验收：编辑并移动一个节点，关闭后重新打开，内容和位置仍在；删除后可以撤销；复制的引用能解析到同一节点。

## 第二阶段：增量整理

状态：已实现 Codex 手动链路需要的带来源追加/更新、整批原子校验、重复更新去重、过期生成版本拒绝和人工层保护。类型在 `src/integration/types.ts`，校验与应用在 `src/integration/update.ts`。当前接口不自动删除生成内容，不提供通用操作协议或模型独立服务；保留人工删除记录。

- 将一轮对话转成带来源的增量变更。
- 验证输入后再应用到图；无效变更不能部分破坏已有内容。
- 重复轮次去重，保护用户修改、关系和删除记录。
- 保留不确定性，分开处理用户疑问和 AI 探索建议。

验收：至少覆盖学习型、方案讨论型和多次分叉的示例。重复整理不产生副本；人工改过的字段保持原样；来源可追溯；自动整理不会打开预览。

这一阶段优先为更新规则写有意义的测试，包括重放、删除、合并引用、过期变更与人工编辑冲突。

## 第三阶段：一个宿主中的手动闭环

状态：Codex 已验证。通过 repo skill、只读 app-server、CLI 与本地预览 API，已用当前真实会话完成浏览器人工修改、再次整理保护和节点引用回读。操作、来源和验证细节见 [Codex 集成说明](codex-integration.md)。

用户安装已补齐：预先打包的 CLI/画布/skill，一次安装配置用户 skill，支持存量项目；查看时自动启动服务，私人数据位于项目之外。版本与下载方式见 [安装说明](installation.md)。

选择可用能力最明确的一个宿主先接通，Codex 为优先验证对象。先确认实际接口，再决定使用 skill、CLI、MCP 或其他适配方式。

- 主动整理当前对话。
- 主动打开预览。
- 复制节点引用，在原对话中让 agent 读取上下文并继续。
- 验证 Devbox 到用户浏览器/预览面的访问路径。

验收：在真实宿主中完成一轮从对话到画布、再从画布回到对话的过程；明确列出支持项和限制。原生 `@` 自动补全和宿主内嵌界面尚未验证，不能作为现有能力承诺。

## 第四阶段：可选自动化与第二个宿主

状态：尚未实现；手动整理不会自动触发每个轮次的任务。

- 验证每个宿主是否有可靠的完整轮次事件。
- 提供用户主动启用和关闭的配置入口。
- 对触发事件去重，避免整理自己触发新的整理循环。
- 自动更新只处理已有授权的对话内容，保持预览打开状态不变。
- 复用核心数据契约接入另一个宿主。

验收：配置前不自动运行，启用后按完整轮次更新，关闭后立即停止；缺少可靠触发能力的宿主仍可手动使用。

## 建议的首批任务

1. 确定数据契约和三个小型对话样例，明确用户编辑保护规则。
2. 做可编辑的明暗画布原型，验证节点密度和详情布局。
3. 实现并测试增量变更应用器。
4. 接通一个宿主的手动整理、预览与引用闭环。
5. 验证自动触发，再增加第二个宿主。
