# 产品规则

本文记录当前讨论确定的产品方向；具体数据结构和集成方式仍可在原型阶段调整。

## 用途

对话自然分叉后，用户仍然能够看清整体、找到已有结论和未展开的方向，并回到其中一条支线继续聊。画布同时承接解决问题、学习新知识和开放探索。

## 整理与打开分开

- 提供主动整理入口。
- 自动整理需要用户显式配置，默认关闭；目标触发时机是一个完整对话轮次结束，而非每个流式片段。
- 整理只更新数据，不主动打开、聚焦或打断当前界面。
- 提供主动打开预览的入口；预览可以关闭或收起。
- `/canvas`、`/canvas update` 仅是此前讨论的交互意图示例，最终名称和支持方式由宿主适配验证决定。

## 提炼什么

按实际内容提炼，避免为每段对话强行套用固定模板：

- 背景、动机、目标、约束和偏好。
- 主题、概念、机制、解释、例子及其关系。
- 方案、比较维度、取舍、已经做出的决定。
- 未解决的问题、假设、不确定性和适用边界。
- 来源，以及随着讨论发生的修正或理解变化。
- 与当前主题相关的可选探索建议。

不是每条消息都对应一个节点。优先保留能够帮助回忆和继续讨论的信息，合并重复内容，控制默认视图的密度。

用户提出的问题和 AI 建议需要区分；AI 建议用轻量的虚线节点承接。建议经过实际讨论后才转成已有讨论的一部分。聊过某个知识点不等于用户已经掌握它。

## 画布与阅读

- 默认只显示节点、连线和极少量视图控制。
- 节点标题尽量直接表达内容；必要时加一行简短摘要。
- 背景可以作为普通折叠节点，不固定占用页面顶部。
- 节点详情按需展开，和节点保持一致的边界与文字对齐。
- 展开后可查看原讨论、复制稳定引用。
- 选择节点只改变查看状态，不自动触发 agent。
- 引用节点后，在原对话里继续沟通；画布不放第二套聊天输入框。
- 视图设计覆盖浅色和深色。能够获取宿主主题时跟随宿主，否则独立预览跟随系统。

## 用户编辑

- 双击节点编辑标题和摘要。
- 选中后的轻量菜单承接补充、连接、合并和删除。
- 用户可以拖动节点调整位置。
- 编辑可以撤销；保存只修改画布，不改写原对话或自动发送消息。

自动整理必须尊重用户操作：

| 操作 | 后续更新规则 |
| --- | --- |
| 修改标题或摘要 | 保护用户改过的字段；新信息作为补充或待采纳修改 |
| 调整连接 | 保留用户建立或移除的关系 |
| 移动节点 | 保留用户位置；新增内容不打乱整个画布 |
| 删除节点 | 同一段旧内容重放时不重新生成；删除可撤销 |
| 合并节点 | 旧引用仍能找到合并后的节点 |
| 手动新增内容 | 作为用户笔记保留，不冒充原对话中的事实 |

## 视觉方向

灰阶、正常产品字号、细边框和稳定间距。背景使用平整色面，网格应极弱或默认隐藏。通过内容、排版和少量线型表达层级。概念图的微小纹理不应当作实现所需的设计资产。

已讨论并排除的常驻元素包括：大标题区、背景/关注/学习方式信息条、面包屑、固定详情栏、状态图例，以及独立聊天输入框。

## 需要通过原型验证

- 在较窄预览区域和更多节点下，文本是否仍然可读，折叠是否帮助找到支线。
- 来源定位与复制引用是否足够自然。
- 用户编辑和 AI 增量更新是否能同时保持内容正确与布局稳定。
- 各宿主是否提供预览、完整轮次事件、原生引用输入等能力；可用范围分别记录。
