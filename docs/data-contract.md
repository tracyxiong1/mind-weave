# 画布数据契约 v1

画布类型定义在 `src/core/types.ts`，人工操作在 `src/core/model.ts`，恢复验证在 `src/core/persistence.ts`。Codex 整理协议在 `src/integration/types.ts`，整批应用在 `src/integration/update.ts`；真实画布外层由 `src/core/live.ts` 校验。

## 已实现的文档边界

每张画布是一个 `schemaVersion: 1` 的 JSON 文档：

| 字段 | 内容 |
| --- | --- |
| `id` / `sessionId` | 稳定画布身份、示例或真实 Codex 对话身份 |
| `generated` | `revision`、按稳定 ID 索引的原始节点与关系；用户操作不改写它们 |
| `user.fields` | 按字段覆盖的标题/摘要、操作 ID、基础生成修订号与时间 |
| `user.notes` | 手工新增节点；`kind: note`、来源为空 |
| `user.edges` | 用户新增关系 |
| `user.removedEdges` | 移除的关系、原始关系成员 ID 和端点记录 |
| `user.tombstones` | 删除的节点 ID、来源 ID 与时间；不物理删除原始内容 |
| `user.aliases` | 合并前 ID → 保留的 ID，可连续映射 |
| `view` | 独立的位置/固定标记、展开、选中、平移/缩放与主题偏好 |
| `history` | 最近 40 步的字段差异、基础修订号与操作时间；支持持久化撤销/重做 |

节点包含 `id`、`title`、`summary`、`details`、`kind` 和 `sourceIds`。`kind` 为讨论、未讨论的建议或用户笔记；聊过某主题不代表掌握它。关系有稳定 ID、两个端点和关系名称，当前连接按无向节点对去重。

## 展示与保护规则

`materialize(document)` 合成展示节点/关系，不修改存储的原始节点：

- 标题和摘要按被用户修改的字段覆盖，未修改字段继续取自生成结果。
- 移动只改 `view.positions` 并记录固定标记，不修改内容。
- 手工笔记独立保存，不增加对话来源。
- 合并以保留节点的标题/摘要为主，保护这两个字段；被合并的内容、人工修正和来源仍在成员中，可在节点详情中查看。笔记成员保持用户来源标记。
- 别名解析后去除自环并合并重复关系；用户移除关系会抑制同一当前节点对的关系。
- 删除保留成员 ID 与来源 ID。已删除节点以及具有相同稳定来源 ID 的旧内容不展示，关联关系也不展示，不产生悬空连线。
- 撤销只恢复操作影响的字典条目，不回滚无关生成内容、其他位置、主题或视口。撤销合并会恢复旧节点的独立身份。

核心操作在克隆文档上完成，非法目标或内容抛错，原文档不变。保存和恢复检查结构、身份、坐标、别名循环、关系端点、笔记来源及撤销负载；损坏和未知版本保留原始存储，阻止自动覆盖。

## 阅读层次与展示布局

连接较多的讨论节点作为视觉阅读锚点，使用更大的标题、轻微底色和一行摘要；这不改变节点内容，也不推断其为已达成的结论。其他讨论支线折叠时以标题为主，摘要在展开后显示。展开摘要比补充说明更突出；较长说明默认预览三行，可继续展开；来源仍按需查看。建议与用户笔记保留原有身份标记。

`view.positions` 是保存的布局锚点，而非每帧展示位置。`src/core/layout.ts` 根据节点的实际测量高度推导展示坐标，同列或相交的后续节点向下避让，留出 40 个画布像素的间距。展开、原文、长摘要与编辑态都使用同一逻辑；折叠后重新从保存的锚点计算。临时偏移不写入文档，不修改固定标记，也不记录撤销，因此现有 v1 数据无需迁移。

拖动时固定其他节点的展示位置，为被拖节点计算最近空位；落点通过已有 `move` 操作保存，只记录一步撤销。键盘移动与新增笔记也选择空位。连线端点、适应画布和稳定引用定位使用同一组展示坐标，避免视觉节点与操作目标脱节。恢复已有重叠锚点时仍会避让，但保留原始保存数据。

## 来源

图数据和对话消息分别放在 `src/data/<sample>.graph.json` 与 `<sample>.conversation.json`。来源结构为：

```ts
interface Source {
  id: string;
  sessionId: string;
  messageId: string;
  start: number;
  end: number;
}
```

范围采用 JavaScript 字符串索引（UTF-16、包含 `start`、不包含 `end`）；摘录直接从对应原始消息切片。界面可查看角色、消息序号、摘录和完整消息，不构造宿主链接。样例来源 ID 是版本化样例内的稳定定位身份。

真实 Codex 消息 ID 根据轮次 ID 和消息 ID 哈希生成，追加捕获不会改变旧 ID。整理提交真实 `messageId` 与精确连续摘录，应用器校验文本一致后按消息 ID、start 和 end 生成 source ID。旧来源保留且去重；不能用随机新 source ID 绕过删除记录。原始消息发生变化会停止捕获；只读原文保存在本地运行目录。

## 稳定引用

```text
mindweave://canvas/<canvasId>/node/<nodeId>
```

ID 限于字母、数字、下划线和连字符，最长 100 个字符。引用不包含标题或数组序号。`parseReference` 验证格式，`resolveReference` 检查画布、别名与删除记录，并返回节点或明确状态。界面提供粘贴定位；页面 hash 的 `ref` 参数也使用同一个解析器。

Codex skill 通过 CLI `read` 从权威文件读取最新合成节点、关系和原文摘录。内置样例仍在浏览器中定位。系统协议注册和原生 `@` 补全尚未实现。

## Codex 增量应用与持久化

`GraphUpdate` 带 `schemaVersion`、唯一 `id`、`canvasId`、`sessionId`、`baseRevision`、节点提案与关系。它只追加或按稳定 ID 更新生成内容；省略旧节点/关系不会删除。discussion 必须有真实来源，suggestion 可无来源；不得覆盖用户笔记，不得将已讨论节点退回建议，也不能让旧关系 ID 改指向其他端点。

- 完整验证后整批原子写入；假的摘录、无效身份与悬空关系不会部分应用。
- 同 ID、同内容更新去重，JSON 属性顺序不影响重放；同 ID 改内容报错。新更新的旧 `baseRevision` 被拒绝，需重新捕获并整理。
- 生成更新不改人工层或撤销记录，旧节点位置保持；新节点选择空位。人工删除、关系移除和别名合并仍通过 materialize 生效。
- 权威记录外层包含文件 `version`、画布 document、对应原文 conversation、sample 来源索引、connection 和私人访问凭据/去重账本。HTTP 只返回公开数据部分，真实文件不作为静态资源暴露。
- 浏览器以 version 保存人工编辑和视图，不能修改 generated。与 Codex 生成更新并发时安全重试保留草稿；检测到另一页面的人工内容/位置修改时停止自动覆盖，保留草稿供导出和恢复。
- 原子文件替换与跨进程锁串行化 CLI 与浏览器写入；损坏文件保持不变。浏览器有独立的未确认草稿备份，关闭前尝试保存。

输入示例、真实接口和运行边界见 [Codex 集成说明](codex-integration.md)。更新不打开预览，页面在编辑、拖动或表单结束后安静读取新内容，不主动改变视口或焦点。

## 后续扩展

通用操作型增量协议、每轮自动触发和第二个宿主尚未实现。扩展仍需遵守：

- 增量包含唯一更新/轮次 ID、基础修订号、操作与真实来源；先验证，整批应用或整批拒绝。
- 同一更新重放不产生变化；过期基础修订重新合并，不能覆盖人工字段。
- 用稳定来源身份识别删掉的旧内容；新讨论的新信息可补充，不能悄悄恢复旧内容。
- 保留用户新增或移除的关系、固定位置与合并引用；新节点在局部安排。
- AI 建议经过实际讨论后才可变为讨论内容。
- 自动整理不打开页面、不抢焦点；预览由明确操作打开。

格式升级需要新增明确迁移，当前不会尝试猜测未知版本。暂不引入复杂同步框架；多人实时协作、导入与跨设备迁移尚未实现。
