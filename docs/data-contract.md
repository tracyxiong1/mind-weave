# 数据与更新契约草案

这是供原型使用的设计草案，不代表已经实现的格式或 API。首个实现任务需要把本文收敛为版本化的数据结构及样例。

## 三类数据分别保留

1. **讨论与整理结果**：对话来源、节点、关系，以及最新应用的轮次。
2. **用户修改**：按字段记录的编辑、手动新增、删除、合并和关系调整。
3. **视图状态**：位置、折叠、选中与缩放；移动节点不改变内容含义。

展示结果由这三类数据共同组成。避免让模型直接重写包含人工修改的整张图。

## 最小实体

| 实体 | 所需信息 |
| --- | --- |
| Canvas | 稳定 ID、格式版本、会话标识、图修订号 |
| Source | 宿主、会话、消息/轮次标识、可定位范围；不得虚构定位链接 |
| Node | 稳定 ID、标题、摘要、来源、可选的内容类别与不确定性 |
| Edge | 稳定 ID、两个端点、关系含义、来源或用户创建标记 |
| User edit | 操作 ID、对象 ID、修改字段及其值、基于的修订号 |
| Tombstone | 已删除对象及对应的来源身份，用于阻止旧内容重放时复活 |
| Alias | 合并前 ID 到当前 ID 的映射，让旧引用仍然有效 |
| View state | 用户位置、是否固定、折叠和视口状态 |
| Update | 唯一更新/轮次 ID、基础修订号、增量操作与来源 |

## 应用更新的约束

- 一次增量要么完整应用，要么不应用；先检查对象、端点和来源引用。
- 同一个更新 ID 重放不产生变化。
- 过期基础修订需要重新合并或重新生成变更，不能覆盖较新的人工编辑。
- 用户保护某个字段不代表冻结整个节点；其他未修改字段仍可更新。
- 已删除内容通过稳定来源身份识别，不能靠模型换一个节点 ID 就绕过删除。
- 新的讨论可以补充新信息，但不应悄悄恢复用户删掉的旧内容。
- 合并保留来源与旧 ID 映射；删除或合并时同步处理关系，避免悬空连线。
- 自动更新保持用户固定的位置；没有位置的新节点在局部安排。
- 用户笔记有自己的来源类型，不能被标成对话原文。
- 撤销是明确的反向操作；遇到后续自动更新时，不应回滚无关的新内容。

## 引用与来源

引用使用稳定身份，而非容易变化的标题或数组序号。展示文本可以使用标题，解析依赖画布 ID 与节点 ID。原生 `@` 输入是体验目标；首个适配可以使用复制引用加 agent 读取来验证流程。

来源能定位时展示原文入口；不能定位时应明确显示可用的摘录或定位信息。画布中的用户编辑不修改原始消息。
